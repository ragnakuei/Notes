# 手機版瀏覽器瀏覽 404 頁面變成下載檔案，但 PC 版瀏覽器正常

已知有相同行為的瀏覽器有：Safari、Chrome

場景：

-   訪問至非預期的頁面只想用 404 來統一回應，避免曝露過多的訊息
-   全站統一在 Response Header 加上 X-Content-Type-Options nosniff

部份程式碼如下：

```cs
/// <summary>
/// 移除不必要的 Response Header
/// </summary>
public class RemoveResponseHeaderMiddleware
{
    public RemoveResponseHeaderMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    private readonly RequestDelegate _next;

    public async Task Invoke(HttpContext context)
    {
        context.Response.Headers.Remove("X-Content-Type-Options");
        context.Response.Headers.Add("X-Content-Type-Options", "nosniff");

        await _next(context);
    }
}
```

問題：

> Response Header X-Content-Type-Options 設定了 nosniff

判斷可能原因：

> 手機版瀏覽器確實遵守了 X-Content-Type-Options 的要求，無法判斷該 Response 的 MIME
> AI 針對此問題的回覆中，其中一點提到：如果 Response 並未指定其 Content-Type 時，就會依照 Response Body 來動態判斷其 MIME !
> 而 404 頁面，本來就不需要額外給定其 Response Body ，自然就不需要給定其 Content-Type
>
> 猜測是經過瀏覽器的判斷後，以檔案下載的方式處理 !

資安風險：

> AppScan 列為低風險

解法：

> 加上下面的 Middleware

```cs
app.Use(async (context, next) =>
        {
            context.Response.OnStarting(() =>
                                        {
                                            if (context.Response.StatusCode == (int)HttpStatusCode.NotFound)
                                            {
                                                // 避免 404 頁面因設定 Content-Security-Policy 而變成下載檔案
                                                context.Response.Headers.Remove("X-Content-Type-Options");
                                            }

                                            return Task.CompletedTask;
                                        });

            await next(context);
        });
```
