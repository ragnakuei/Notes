#### 安裝 pwsh
呼叫 Playwright 的工具，都需要透過 pwsh 指令 ( PowerShell )
winget install --id Microsoft.Powershell --source winget


#### 建立初始測試步驟

- dotnet new nunit -n PlaywrightTests
- 將專案加到方案中
  - dotnet sln add PlaywrightTests/PlaywrightTests.csproj
- cd PlaywrightTests
- dotnet add package Microsoft.Playwright.NUnit
- dotnet build
- 安裝瀏覽器
  - pwsh bin/Debug/net8.0/playwright.ps1 install
- 貼上官方程式碼 UnitTest1.cs
- dotnet test


執行指定的 Test Class
- dotnet test --filter "ExampleTest"
- 後方指定的是 class 名稱

#### Debug 方式

```powershell
$env:PWDEBUG=1
dotnet test --filter "ExampleTest"
```

執行後，會直接停在瀏覽器開啟狀態，後續可 resume 執行 或 step over 執行 !


#### 使用 Codegen 工具

```powershell
pwsh bin/Debug/net8.0/playwright.ps1 codegen demo.playwright.dev/todomvc
```

左方是 Codegen 使用 Playwright 預設的瀏覽器 Chromium
右方是 Inspector，用來看產生的程式碼

Target Library 就是轉成 console 可直接跑的程式 !

#### 儲存及使用登入資訊
儲存登入資訊
> pwsh bin/Debug/net8.0/playwright.ps1 codegen https://localhost:7078/ --save-storage=auth.json

讀取剛才儲存的登入資料，發現一進入頁面已經登入了 !
> pwsh bin/Debug/net8.0/playwright.ps1 codegen https://localhost:7078/ --load-storage=auth.json

不讀取登入資料，進入頁面時，未登入
> pwsh bin/Debug/net8.0/playwright.ps1 codegen https://localhost:7078/

auth.json 會存在執行的目錄下，內容為 Cookie 的資料


登入不同角色並儲存為不同檔案，在測試時，就可以有多個角色的身份同時測試 !

#### 儲存 request
儲存檔案的起始位置在 bin 資料夾中
後續測試時，可以修改 .har 檔內容，來達成 mock api 的效果 !
必須執行成功，才會儲存 .har 檔案 !
api 路徑區分大小寫 !

> pwsh bin/Debug/net8.0/playwright.ps1 show-trace bin/Debug/net8.0/playwright-traces/PlaywrightTests.MockLoginTest.FakeLogin.zip

可以看個截圖、request / response 的詳細狀況 !

#### 細項

- 建議使用 node.js 版，原因：
  - .net 版沒有像 node.js 版的 playwright.config.ts 可以預先指定測試的各個平台，.net 只能透過程式來指定 !  基本上建議使用 node.js 版會比較省工 !
  - pwsh 下的 playwright 工具，沒有 show-report 功能 !
  - 有 UI Mode
    - 可以透過 open snapshot in the new tab 去看當下網頁的狀況 !
    - watch mode - 程式修改後，立即自動重跑測試 !
  - cli 整理成統一的界面
  - .net 需要 playwright.ps1 及 dotnet cli 互交使用 !
- 繼承 PageTest 時，該 class 內的 Page instance，是共用狀態的 ! 
- 程式
  - name 是部份比對，如果要完整比對，要額外加 exact: true !




#### 寫測試觀念

不好的定位點，難維護
- css class
- xpath


不需要對 Codegen 的 code 重構，保留產生的結構即可，方便之後調整 !

當程式加入版控後，保留 Codegen 產生的 code，這樣比對差異上，會更為明確 & 不需要重複重構 ! 

好的定位點
- aria-label
- placeholder
- 如果網頁的結構 ( 從人的角度去看的結構 ) 太差，寫 Playwright 就會很吃力 !
